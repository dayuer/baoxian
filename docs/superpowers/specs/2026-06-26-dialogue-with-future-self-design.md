# 设计文档：与未来的自己对话 — 自助式家庭保障缺口诊断

**日期**：2026-06-26
**项目**：BAOXIAN · 生命的建筑学
**状态**：已通过 brainstorming 验证，待实现计划

---

## 一句话定义

一个让用户**和"未来的自己"对话**、自己把家庭保障缺口算清楚的自助式诊断体验。不被打扰、没有顾问、不逼单。

## 设计哲学

保险的本质是"用确定的小成本对冲不确定的大冲击"。多数保险网站失败在于产品堆砌、参数对比，用户没有共鸣。本产品反其道而行：

- **先共情，再点醒，最后接住**——不先讲产品，先帮用户看清"自己在怕什么、在守护什么"。
- **对话感但零推销**——保留"被理解"的温度，但对面不是顾问，而是"未来的自己"，彻底去掉销售压迫感。
- **诚实建立信任**——明确讲方案"不能做什么"（等待期、除外、只保身故不保患病等），比一味强调保障更可信。

## 体验主线：六幕

单页渐进式对话流，一屏一焦点，对话气泡逐条浮现（非问卷翻页）。

| 幕 | 名称 | 体感 | 交互要点 |
|---|---|---|---|
| ① | 开场 · 不问产品问"谁" | 情绪入口 | "你生活里有没有一个不能倒下的理由"，黑底留白，单一入口 |
| ② | 勾勒 · 你守护的那个家 | 被听见 | 轻量输入（点选为主、少打字），"未来的我"温柔复述每个回答 |
| ③ | 测算 · 一起算缺口 | 边聊边算 | 输入开支/年期/负债/缓冲，可视化实时生长 |
| ④ | **啊哈 · 看见那个数字** | 情绪峰值 | 黑底，巨大红色缺口数字缓缓浮现，配"这个数字，可能从没人帮你算过" |
| ⑤ | 接住 · 缺口怎么被盖住 | 方案=答案 | 讲清能盖什么、成本量级，**诚实说不能做什么** |
| ⑥ | 带走 · 属于你的东西 | 不被催 | 报告(A) + 我的方案空间(B) + 克制的门(C) |

## 技术架构

延续现有栈：React 19 + Vite + TypeScript + Tailwind 4。现有 `App.tsx` 品牌站作为入口/门厅，对话体验为新核心模块。

```
src/
├─ App.tsx                    # 路由：品牌门厅 / 对话体验 / 我的方案
├─ brand/                     # 现有"生命的建筑学"落地页，作为开场入口
├─ dialogue/                  # 核心：与未来的自己对话
│  ├─ DialogueFlow.tsx        # 六幕状态机，驱动对话推进，单向数据流
│  ├─ acts/                   # ①~⑥ 每一幕一个组件，职责单一
│  ├─ Message.tsx             # 对话气泡（"未来的我" / 用户回答）
│  └─ inputs/                 # 点选、滑块、数字输入等轻量输入控件
├─ engine/
│  ├─ gapCalculator.ts        # 纯函数：FamilyProfile → GapResult，可独立测试
│  └─ types.ts                # 数据模型
├─ visual/
│  └─ GapReveal.tsx           # 第④幕冷峻巨数动画
└─ report/
   ├─ Report.tsx              # 缺口报告（可下载/分享）
   └─ persistence.ts          # localStorage + URL 编码状态
```

### 设计原则

1. **测算引擎是纯函数**：`gapCalculator(profile) → result`，不碰 UI，集中所有算账逻辑，对话与报告共用。
2. **对话状态机集中管理**：六幕推进、用户答案、可回退，由 `DialogueFlow` 一处持有，单向数据流。
3. **无后端起步**：留资/报告用 localStorage + URL 编码实现"我的方案"私人链接，零后端即可上线。未来需要邮件寄送报告或真人接入时再接最小后端。

## 数据模型与测算引擎

```ts
// engine/types.ts
type Dependent = {
  role: 'spouse' | 'child' | 'parent'
  age: number
  hasIncome: boolean
}

type FamilyProfile = {
  dependents: Dependent[]
  monthlyExpense: number            // 家庭月开支
  educationPerChildYearly?: number  // 国际教育等专项
  mortgageBalance: number           // 负债余额
  savings: number                   // 现有缓冲
  residencyAbroad?: boolean         // 影响方案体系分支（境内/香港）
}

type GapResult = {
  livingNeed: number      // 生活开支 × 需供养年数
  educationNeed: number   // 教育专项
  debt: number
  totalNeed: number
  buffer: number          // 已有缓冲
  gap: number             // 缺口（第④幕那个数字），下限 0
  preparedRatio: number   // 已准备百分比（报告进度条）
  breakdown: { label: string; value: number }[]  // ⑤翻译成人话
}
```

### 测算逻辑（纯函数）

- 需供养年数 = 最小孩子到 18 岁（或可配置到大学毕业）的年数
- `livingNeed = monthlyExpense × 12 × 年数`
- `educationNeed = 教育/年 × 孩子数 × 各自剩余学年`（可选通胀系数）
- `totalNeed = livingNeed + educationNeed + debt`
- `gap = max(totalNeed − buffer, 0)`
- `preparedRatio = buffer / totalNeed`

### 测试策略（TDD）

先写 `gapCalculator.test.ts`，把真实参考用例作为第一个测试：
> 三个孩子（3 岁、1.5 岁 ×2）、月开支 10 万、房贷 400 万、教育 20 万/孩/年、存款 500 万、供养至 18 岁
> → 生活 1980 万 + 教育 960 万 + 负债 400 万 = 总需求 3340 万 − 缓冲 500 万 = **缺口 2840 万**

（注：本期引擎用不含通胀、教育算至 18 岁的基础公式，得 2840 万；对话中口算的 ~3800 万额外计入了学费通胀与大学阶段，属后续迭代的可选增强。）确保引擎结果与手算一致，再写实现。

## 错误处理与边界

- 输入校验：负数/空值给温柔行内提示，不用报错弹窗（破坏体感）
- 缺口为 0 或负：转成"你已经准备得很好"的正向叙事，不羞辱用户
- 可随时回退修改任一答案，缺口实时重算
- localStorage 不可用（隐私模式）：降级为纯 URL 编码，不阻断流程
